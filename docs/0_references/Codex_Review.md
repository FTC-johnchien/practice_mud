# Codex 文件與程式一致性審查

> **審查日期：** 2026-11-02（Asia/Taipei）  
> **審查範圍：** `docs/1_requirements/`、`docs/2_specifications/`、`docs/3_task_lists/` 之全部 Markdown 文件（盤點共 68 份），並依文件引用抽查／核對相關 Java、JavaScript、HTML、JSON 與測試。  
> **排除：** `docs/2_specifications/ARCHITECTURAL_DECISIONS.md` 已決議事項不作為待修缺陷；該檔只用來確認審查邊界。  
> **方法與限制：** 靜態閱讀及搜尋文件、實作和測試來源；未執行測試或建置。本報告不將明確標為待辦、候選或長線藍圖的功能判定為已交付功能。

## 審查摘要

本輪確認一項 L1 需求與現行 UI／任務描述的落差：需求要求移除任何可輸入命令列，但遊戲頁仍提供可開啟的終端，允許輸入並送出 MUD 指令；FE1 任務將終端描述為「開發者終端」，卻未限定開發環境或標示為需求例外。

結構化 Action 全面遷移在 M9 任務中明確列為未完成；離線快取與斷線排隊則位於 L2 長線演進藍圖。兩者是已標示的未完成工作，不當作已實作功能。Copilot 舊 review／更早 Codex review 的部分主張已過時或缺乏當前證據，本報告列出核對結果。

## 已確認差異

### CDR-01｜零命令輸入需求與遊戲內終端相抵觸

- **優先級：** P1（需求／產品定位需一致）
- **文件證據：** `UI_UX_REQUIREMENTS.md` 核心定位明定「徹底除役 MUD 指令輸入框與文字房間移動」；第 1 節更要求「徹底移除任何打字輸入命令列」。`FE1_CORE_STATE_TASKS.md` 卻把原輸入框下架後轉向 `~` 呼叫的「開發者終端」列為已完成，沒有說明該終端僅限開發環境或正式介面例外。
- **程式證據：** `src/main/resources/static/index.html` 的一般遊戲頁包含可見終端入口（約第 248、653 行）及 `dev-cmd-input` 文字欄（約第 619 行）；`src/main/resources/static/js/app.js` 讀取欄位並呼叫 `sendCmd`（約第 133–137 行）。因此從目前頁面與程式可見行為來看，玩家仍能輸入並送出指令。
- **判定：** 「移除舊底欄命令輸入框」已完成，但未滿足 L1 的「不提供任何命令輸入列」字面要求。稱為開發者終端並不構成環境隔離；目前未見正式／開發模式的顯示防護。
- **建議：** 依產品意圖選定一個明確契約：若終端只供開發，將其限制在開發模式並在 FE1 標清例外與驗收方式；若終端屬於預期玩家功能，修訂 L1 的零命令輸入表述，說明玩家可使用的命令範圍。同步更新 FE1 已完成項目與驗收描述。

## 已核對但不列為缺陷

- **SAN／魔化：** L1 §5.1 明確保留 SAN 護盾與 SAN 歸零後的單一【精神萎靡】弱化，並除役隨機發狂、自殘、背叛等機制。R9、M3.1、M4 與 HUD 對應保留 SAN／弱化，未構成文件矛盾；未將其重複列為問題。
- **`chipRate` 存檔：** 舊 review 指稱 `SaveData` 缺少此欄位，但現行 `SaveData` 有 `chipRate`（預設 12），`SaveGameService` 寫入及載入時均處理該值，`SaveGameServiceTest` 也包含存讀檔案例。舊結論已不適用。
- **結構化 Action：** M9 規格描述標準 Action 契約，而 `M9_STATE_PIPELINE_TASKS.md` 將全面收斂列為未完成的 M9-1。現行 `cmd-dispatcher.js` 和 `websocket.js` 仍以 `{type: "INPUT", text: cmd}` 傳輸字串命令，表示任務尚未完成；任務狀態與程式現況相符。這是已知待辦，不另列文件錯位。
- **離線快取／斷線排隊：** FE1 規格將 Service Worker 與離線能力放在「未來架構演進」下的長線藍圖；現行程式未見 Service Worker 或離線指令佇列。因文件已標示為未來規劃，不能判為已承諾功能失實作。若團隊希望追蹤其交付，再補入 L3 未來任務即可。
- **Copilot 舊 review 的其他線索：** 舊版提及的地圖圖例、屬性、Schema draft、EQUIP/slot 等問題，未在本輪以可重現的直接證據確認為當前且未解的差異，因此不沿用為本次缺陷。Copilot 現行版提出的離線項目也應以上述「已標長線藍圖」狀態解讀，而不是與當前需求衝突。

## 建議處理順序

1. 先裁定開發者終端是否為 L1 例外，並確保文件、正式 UI 顯示行為及 FE1 驗收一致。
2. 按 M9-1 任務完成結構化 Action 遷移；完成前保留待辦狀態，不宣稱協定已全面收斂。
3. 若離線能力納入可交付範圍，建立對應 L3 任務與驗收條件；否則維持長線藍圖標示。
