## 1. 專案現況盤點與差距分析 (Gap Analysis)

### 1.1 現有已實作並跑通之機制 (Working Core)
目前後端已具備高質量的狀態核心架構，遵循 **基準心跳計數器模型（1 Tick = 500ms）**，並通過完備的單元測試（`BuffDebuffSystemTest.java`）：

1. **五大底層結算分類 (`BuffCategory`)**：
   - `SHIELD`（傷害吸收護盾）：支援多重護盾共存，受擊時依「最短剩餘時間優先（Shortest Duration First）」依序扣抵，護盾歸零破碎化為光屑，穿透傷害扣減本體 HP。
   - `HOT`（週期性治療）：依週期（`tickIntervalTicks`）跳算恢復氣血。
   - `DOT`（週期性傷害）：依週期跳算造成陰煞傷害，支援致死判定與最多 5 層疊加。
2. **生命週期與堆疊刷新規則（WoW 規則）**：
   - 相同技能狀態刷新持續時間，護盾取最大值不無限膨脹。
   - 支援 `maxStacks` 層數限制與倍數跳算。
3. **戰術方針 AI 防呆（Gambit AI）**：
   - 同伴具備 `TARGET_LACKS_BUFF`、`BUFF_TIME_LESS_THAN` 等條件檢定，已掛狀態時不無腦重複施放。
4. **精神與狂暴狀態（Madness & Sanity FSM）**：
   - `MadnessState`（`SANE` 正常 $\to$ `CHAOS` 走火入魔混亂 $\to$ `SEALED` 鎮魔定身 $\to$ `ABERRATION` 古神異變）。

## 2. 經典與現代 RPG 狀態體系借鑒與分析

為了讓太陰地宮的戰鬥體系兼具「高戰術性」、「嚴謹數值」與「DRPG 經典壓迫感」，我們調研了五大標竿 RPG 體系：

```
                    ┌─────────────────────────┐
                    │  五大經典 RPG 體系借鑒   │
                    └────────────┬────────────┘
         ┌──────────────┬────────┴───────┬──────────────┬─────────────┐
         ▼              ▼                ▼              ▼             ▼
   【勇者鬥惡龍】    【最終幻想】     【魔獸世界】    【女神轉生】   【辟邪除妖】
   Dragon Quest   Final Fantasy         WoW         SMT/Persona     Wizardry
   極簡清晰/命中   時序條/狀態反制   驅散/心跳/護盾   屬性連鎖/降防   殘酷/不可逆/探索
```

### 2.1 Dragon Quest（勇者鬥惡龍）
* **核心哲學**：狀態數值極度凝練，效果直接影響行動回合與攻防量級。
* **代表狀態**：
  * **幻惑（マヌーサ / Dazzle）**：物理命中率巨幅下降（命中率壓低至 3/8），法術不受影響。
  * **封咒（マホトーン / Fizzle）**：100% 封鎖魔物與玩家的咒文施展，只能普攻。
  * **倍攻（バイキルト / Oomph）**：下一次或數回合內物理傷害直接乘 2。
  * **睡眠（ラリホー / Snooze）**：無法行動，受到攻擊有機率被打醒。

### 2.2 Final Fantasy（最終幻想）
* **核心哲學**：時序進度條（ATB）互動、異常狀態鏈與即死博弈。
* **代表狀態**：
  * **減速 / 加速（Slow / Haste）**：直接改變行動計時條累積速率。
  * **停滯（Stop）**：時間完全凍結，無法行動，連自身身上的 Buff/DoT 跳算也跟著凍結。
  * **漸減宣告（Doom）**：頭頂出現 30 秒或數回合倒數，倒數歸零立即暴斃。
  * **盲目（Blind）/ 沉默（Silence）/ 石化（Petrify - 全隊石化即判定滅團）。**

### 2.3 World of Warcraft（魔獸世界）
* **核心哲學**：心跳跳算（Tick System）、護盾優先吸收、嚴格的驅散類型分流。
* **代表機制**：
  * **四大驅散標籤**：`Magic`（魔法）、`Curse`（詛咒）、`Poison`（毒素）、`Disease`（疾病）。
  * **短持續時間優先吸收護盾**：多層護盾保護脆弱生命。
  * **急速（Haste）**：縮短共用冷卻（GCD）、加速持續傷害/治療（DoT/HoT）跳算頻率。

### 2.4 真・女神轉生 / Persona 系列（SMT / Megaten）
* **核心哲學**：弱點擊破、屬性異常連鎖（Technical）、卡賈/昆達（-kaja / -kunda）輔助博弈。
* **代表機制**：
  * **屬性連鎖（Technical Combo）**：
    * 冰凍（Freeze）$\to$ 受到物理打擊必爆擊且碎冰解凍。
    * 感電（Shock）$\to$ 無法動彈且物理攻擊 100% 暴擊。
    * 著火（Burn）$\to$ 週期扣血且護甲防禦下降。
  * **三維增減博弈**：
    * 塔爾卡賈/塔倫達（攻擊力 $\pm 25\%$）
    * 拉庫卡賈/拉昆達（防禦力 $\pm 25\%$）
    * 斯庫卡賈/斯昆達（命中/迴避 $\pm 20\%$）
    * 德卡賈（Dekaja 消除敵方全體增益）/ 德昆達（Dekunda 消除我方全體減益）。

### 2.5 Wizardry（避邪除妖 / 辟邪除妖）
* **核心哲學**：極度硬核、不可逆狀態、迷宮探索生存危機。
* **代表機制**：
  * **麻痺（Paralyzed）/ 石化（Stoned）**：戰鬥結束後**不會自動恢復**，隊員如同屍體般需要搬回城鎮解咒神殿花費重金治癒。
  * **骨髓/等級吸收（Energy Drain / Essence Drain）**：魔物直接吸取角色經驗值或境界，造成不可逆的道行倒退（仙道克蘇魯絕佳素材）。
  * **窒息/毒沼**：地牢環境地塊持續累積負面狀態。

## 5. 系統架構重構與演進路線圖 (Implementation Roadmap)

為落實上述體系，建議分四個階段（Phase）穩健迭代，不破壞既有架構：

```
 Phase 1: 結算引擎掛鉤 (P0) ──> Phase 2: EffectType 規範化 (P1)
           │                                 │
           ▼                                 ▼
 Phase 3: UI 全生命週期呈現 (P1) ─> Phase 4: Gambit AI 淨化擴充 (P2)
```

### 5.1 Phase 1: 結算引擎與戰鬥迴圈掛鉤 (P0)
* **目標**：讓屬性修正（`STAT_MODIFIER`）與控場（`CONTROL`）真正生效。
1. **屬性修正接入**：
   - 在 `Party.java:calculateEffectiveStats` 與 `TacticsService:calculatePlayerDamage` 中，遍歷目標實體的 `getActiveBuffs()`。
   - 若含有 `statModifiers`，即時疊加至最終攻防值（如 `ATK_PCT`, `DEF_PCT`, `SPEED_PCT`, `CRIT_PCT`）。
2. **控場限制接入**：
   - 在 `DrpgCombatLoop` 與 `PartyMember.isOnGcd` / 攻擊時機檢驗處，檢查是否掛有 `FROZEN`, `STUNED`, `PARALYZE` 狀態。
   - 若存在凍結或眩暈，跳過本輪攻擊，輸出「身形受制無法行動」戰報。
3. **修復常駐陣法判定**：
   - 修正 `ActiveBuff.isExpired()`：若 `durationTicks == -1`（常駐光環），不視為過期（`remainingTicks > 0 || durationTicks == -1`）。

### 5.2 Phase 2: `EffectType` 枚舉與技能配置重構 (P1)
* **目標**：淘汰冗餘 enum，將 43 種空枚舉收斂為專案真正支援的語意體系。
1. **精簡與規範化**：
   - 淘汰無用、重複的 enum（如同時存在 `BRAVERY`, `COURAGE`, `STRENGTHEN`）。
   - 明確劃分為 5 大枚舉分組（`POISON`, `BURNING`, `FROZEN`, `PARALYZE`, `SILENCE`, `STUN`, `BLIND`, `HASTE`, `SLOW`, `SHIELD`, `HOT`, `STAT_BUFF`, `STAT_DEBUFF`）。
2. **配置範例模板**：
   - 在 `src/main/resources/data/global/skills/` 補齊火系（燃燒 DoT）、冰系（減速/凍結）、雷系（麻痺）技能 JSON 定義。

### 5.3 Phase 3: 前端 UI 全生命週期視覺呈現 (P1)
* **目標**：讓玩家在所有介面皆能清晰感知自身與隊友的狀態。

## 6. 總結與評估建議

| 項目 | 現況評估 | 建議處置 | 預期戰術價值 |
| :--- | :---: | :---: | :---: |
| **護盾 / HoT / DoT** | ⭐⭐⭐⭐⭐ (已完備) | 維持既有心跳計數器模型，擴充技能種類 | 基礎生存與續航線 |

| **控場機制 (Control)** | ⭐⭐ (機制分散) | 收斂 Stun/Silence 至 `ActiveBuff` 統一結算 | 帶來打斷敵方施法與危險招式的策略反制 |
| **EffectType 枚舉庫** | ⭐ (43個多數閒置) | 清理重構，刪除同質枚舉，補齊實裝技能 | 提升代碼純潔度與資料驅動規範性 |

本規劃可作為後續 DRPG 戰鬥深化（Battle Depth Enhancement）的標準指南。建議首先從 **Phase 1（屬性與控場結算連通）** 與 **Phase 3（前端角色面板展示）** 著手，以最小代價收穫最大的玩法反饋！
